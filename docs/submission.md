# 题 D：可观测 AI 任务管线 MVP

项目：**Frameflow / observable-ai-pipeline**。交付：[公开源码](https://github.com/zhangshuyan1160-ops/observable-ai-pipeline) · [源码 ZIP](https://github.com/zhangshuyan1160-ops/observable-ai-pipeline/raw/refs/heads/main/delivery/observable-ai-pipeline-v0.3.0.zip)。运行方法见 [README](../README.md)。

## 1. 实现方式与时间安排

使用 Python 3.12、FastAPI、PostgreSQL、独立 Worker 和原生 HTML/CSS/JS。以动画素材为例，生成 GIF、缩略图和 ZIP；AI 计算及 GPU 指标采用 MOCK。任务状态、检查点、重试、进程中断恢复和文件校验实际执行。

**项目总用时约 8 小时，10 小时以内。** 从 2026-10-12 14:36 开始讨论，到 22:27 完成 v0.3.0 文档版发布，历时约 7 小时 51 分钟，包含调研、AI 辅助开发、测试等待、反馈迭代和发布。这是项目经过时间。[时间记录](evidence/project-timeline.json)

在两天的提交期限内，先完成任务执行与恢复，再补充取消、历史查询和资源等待，最后完善交互、验证和交付文档。选择本机运行和公开源码，省去租赁服务器与部署真实模型的时间。[实施顺序](plan.md)

## 2. 长任务、状态管理与恢复

创建请求返回 202 和任务 ID，计算交给独立 Worker。API 重启或客户端断开后，任务仍保存在 PostgreSQL 中。任务、步骤和每次执行尝试分别记录状态，上游可以查询进度、等待原因、错误及执行历史。

Worker 使用 10 秒租约和 2 秒心跳；失联后由其他 Worker 回收并继续执行。临时错误采用有限重试和退避，永久错误停止；手动重试保留成功步骤与旧尝试。每次写入检查当前 attempt 和 fencing token，拒绝旧 Worker 的迟到结果。执行语义为至少一次。

风格化每 4 帧保存检查点，恢复时重做尚未提交的批次。已完成一次 3607.93 秒的单任务演练，数据库停机和全栈重启后分别从 4、8 帧继续。扩展到真实小时级任务时，需要增加对象存储、容器退出确认、进度超时、资源配额及版本兼容；外部 AI 服务还应保存 provider job ID，避免重复提交付费任务。

## 3. 步骤与依赖

固定 DAG：`probe → extract → stylize → compose → package`，另有 `extract → thumbnail → package`。创建时验证无环，保存定义和参数快照；父步骤全部成功或命中缓存后，子步骤才可领取。

素材检查负责校验，extract 生成帧索引，stylize 分批生成 PNG，thumbnail 与风格化并行，compose 合成 GIF，package 汇总交付文件。昂贵的批次推理适合检查点；合成包含编码器内部状态，失败时整步重做更简单。单个张量算子过细，通常不值得独立持久化。

## 4. 持久化内容

| 数据 | 用途 |
| --- | --- |
| tasks、steps | 输入、依赖、状态、截止时间和检查点，决定恢复位置 |
| attempts、events | 保留每次尝试、错误、恢复起点和状态变化，支持查询与排障 |
| artifacts、cache_entries | 保存产物引用、摘要、版本和来源，支持校验与结果复用 |
| workers、resource_slots | 保存心跳、能力和资源所有权，展示离线与排队情况 |

状态变更与事件在同一事务提交。文件先写入不可变路径，再校验所有权并登记成功；未提交的孤儿文件不会成为成功结果。缓存指纹包含相关参数、处理版本和父产物摘要，只有文件存在且校验通过才复用。模型或 seed 改变时，只重算受影响的步骤及其下游。

## 7. 失败案例与改进

- **队列饥饿**：最初先取前 32 个活跃任务，再筛资源，导致较早的 GPU 等待任务挡住后来的 CPU 工作。改成先筛资源与就绪时间，再限制候选数量；两条 PostgreSQL 回归验证了修复。
- **响应丢失后重复创建**：前端每次点击都会生成新幂等键。改成发送前保存键和参数快照，刷新后重试原请求；真实 API 与数据库验证只有一条任务和创建事件。
- **轮询丢失交互状态**：重建 DOM 会关闭错误详情。改成按稳定标识更新节点，保留焦点、展开状态和滚动位置。
- **CI 环境假设**：测试曾依赖启动脚本创建临时目录。改成测试初始化时自行创建，在 Linux CI 中通过验证。

本地与 Linux CI 已通过 33 项 pytest 和 4 项前端测试。[故障验收矩阵](failure-matrix.md) · [发布验证](evidence/release-v0.3-verification.json)

## 8. 范围与后续扩展

MVP 面向单机固定 DAG。GPU 采用 8 GiB 单槽模拟，支持占用、排队、心跳和超容量拒绝；接入真实 GPU 时需由节点代理确认旧进程退出，并接入 DCGM 与 OOM 分类。fencing 保护结果提交，不能停止失联进程。

下一步可增加多机调度、鉴权、对象存储和孤儿文件清理。当前未提供任意素材上传、通用 DAG 编辑或真实模型推理；Compose 提供配置，尚未完成运行验收。数据库 v1→v2 迁移已实现，工作流定义和检查点的跨版本热迁移属于后续工作。
