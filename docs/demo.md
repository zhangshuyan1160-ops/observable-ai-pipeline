# 五分钟演示与讲解

先按 README 启动并打开 http://127.0.0.1:8765 。

1. **正常流程与接口（约 45 秒）**：新建默认任务；点每个节点查看依赖和 attempt；完成后看 GIF、下载交付包。说明创建 API 立即返回，计算在独立进程。
2. **自动重试（约 45 秒）**：新建任务，故障预设选择“首次失败，自动重试”。界面自动取消缓存。完成后风格化出现 FAILED→SUCCEEDED 两次尝试，probe/extract 仍各一次。
3. **真实中断（约 90 秒）**：新建 32 帧、每批 4 秒、关闭缓存任务。看到风格化至少保存 4 帧后运行 `.venv/bin/python scripts/dev.py interrupt gpu`；两个本地 GPU Workers 被 SIGKILL 后由 supervisor 重启。租约 10 秒内不会立即重领；之后旧尝试 INTERRUPTED，新尝试从已保存帧数继续。
4. **结果复用（约 30 秒）**：正常启用缓存的任务完成后点“相同输入再次运行”。新任务 6 步 CACHED、计算尝试 0。若原任务关闭缓存，首次再运行负责生成缓存，需要再点一次才能全命中。
5. **手动恢复（约 45 秒）**：故障选择“本轮全部失败，手动恢复”，耗尽三次后点击失败步骤的重试按钮。新轮次成功，旧历史保留。
6. **边界解释（约 45 秒）**：GPU 单槽为模拟；fencing 保护结果，不等于停止失联真 GPU 进程；计算至少一次；小时级需对象存储、容器隔离、进度超时、配额和版本兼容。

自动复核：`.venv/bin/python scripts/verify_demo.py`，包括真实 API 与 Worker SIGKILL、检查点、缓存、手动重试和下载摘要。输出到 `docs/evidence/live-demo.json`。不要对别人的运行服务执行故障注入。

长任务参数通过 `/docs` 提交：frames≤64、step_delay≤10 秒、batch_delay≤900 秒、attempt_timeout≤14400 秒、task_timeout≤14400 秒。参数允许较长时限，但这不是已跑过小时级工作负载的证据。

## v0.2 追加演示（约两分钟）

1. 新建 64 帧、每批 4 秒、关闭缓存的任务。展开“任务参数与执行时限”，核对配置。
2. 在风格化运行时点“取消任务”并确认，观察“取消中”到“已取消”；成功上游和尝试历史仍在，GPU 槽释放。
3. 归档已取消任务；在左侧选“已归档”和“已取消”，按任务名搜索，查回任务并“恢复到列表”。归档不删除产物。
4. 解释并发修复：32 个旧 GPU 等待任务不应挡住后来的 CPU 工作，展示 test_task_controls.py 对应回归。
5. 打开 recovery-short.json 和 recovery-hour.json，检查最终 status、恢复帧数、事件数与产物摘要。不要把 RUNNING 报告当作通过。
