## 执行器与恢复

采用 FastAPI、直接 psycopg SQL、PostgreSQL 短事务队列和独立 Worker。每次 attempt 保留执行历史，状态、资源和事件同事务提交。计算与文件生成在事务外运行，提交时检查当前 attempt 和 fencing token。

动画流程实际生成 PNG、GIF 和 ZIP；风格化以 4 帧为检查点单位。缓存按参数、版本和父产物摘要判断，并校验文件。GPU 采用单槽模拟，等待、占用和释放均可查询。

v0.2 增加取消屏障：线程内操作结束后才确认停止，失联时保留“停止未确认”状态。schema v2 迁移保留原任务数据，旧幂等请求的参数归一化保持兼容。

一小时演练运行 3607.93 秒，期间真实停止数据库并重启全栈，分别从 4、8 帧恢复；39 条事件连续，最终交付文件摘要一致，模拟资源槽释放。

## 实际问题及修复

| 问题 | 原因 | 修复与验证 |
| --- | --- | --- |
| CPU 工作被 GPU 等待任务挡住 | 先截取前 32 个活跃任务，再筛资源和就绪时间 | 先筛选再限制候选数；两条回归修改前失败、修改后通过 |
| 测试未推进到指定任务 | 辅助函数假设两次 CPU 领取会推进同一任务 | 改为等待目标步骤达到指定状态 |
| 切换终态步骤后时间线消失 | 重建 DOM 清空资源和事件容器 | 保存最近数据并重绘，浏览器复核 |
| 首次 Linux CI 初始化失败 | 测试临时目录依赖本地启动器的副作用 | pytest 初始化时创建父目录，CI 通过 |
| 模型版本表单正则转义风险 | JS 模板内反斜杠转义 | 移除重复 HTML 正则，保留 Pydantic 校验 |
| 依赖锁漏项 | 初次整理遗漏传递依赖 | 核对包元信息、补齐锁文件并安装验证 |
| 创建响应丢失后重复任务 | 每次点击生成新幂等键 | 发送前保存键和参数；真实 HTTP、数据库及浏览器代理验证原任务只创建一次 |
| 复制参数改变缓存和故障配置 | 复制与复用共用同一操作 | 拆分两个入口，完整复制与两项明确变更分别验证 |
| 轮询关闭错误详情 | 摘要增减导致尝试表格重建 | 增加稳定标识，验证焦点、展开状态和滚动保留 |
| 管线入口箭头朝上、缩放错位 | 固定 SVG 坐标与 CSS 网格不一致 | 按节点边界绘制、ResizeObserver 更新，验证三种视口 |

## 验证与发布

- v0.1 源码包在新建虚拟环境中安装后，19 项测试通过，pip check 通过。
- v0.2 在本地、独立安装环境与 Linux CI 通过 31 项测试；wheel 包含迁移 SQL。打包时使用标准隔离构建，解决运行环境缺少 setuptools 构建后端的问题。
- v0.3 本地通过 33 项 pytest（15.49 秒、0 跳过）和 4 项 Node 测试。浏览器验证首次创建成功但响应丢失后的刷新重试、参数复制、手动恢复、缓存来源和轮询交互。
- Linux CI [run 38262160754](https://github.com/zhangshuyan1160-ops/observable-ai-pipeline/actions/runs/38262160754) 通过 33 项 pytest（31.12 秒、0 跳过）、4 项 Node 测试及 Ruff 检查。
- 管线连线在 1440×1000、1024×900、390×844 视口下检查；五个入口朝右、对齐节点中心并保留 4px 间距。窄屏滚动和节点选择正常。
- 发布通过 GitHub 连接器完成。远程 Git tree 与本地一致，源码 ZIP 匿名下载后摘要匹配。当前包的源码快照与 SHA-256 见 delivery/manifest.json。
