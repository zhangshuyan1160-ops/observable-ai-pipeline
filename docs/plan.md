## 范围和取舍

核心范围包括固定动画 DAG、步骤依赖、持久化状态、有限重试、Worker 中断恢复、批次检查点、缓存与查询接口。任务取消、历史管理和模拟 GPU 资源观察也已完成。

为集中验证恢复机制，计算使用 MOCK，页面使用原生 HTML/CSS/JS，数据库同时承担状态存储和就绪队列。采用本地 PostgreSQL，避免增加 Redis、调度平台或模型运行环境。公开源码满足交付要求，公网部署、SSE、真实 GPU 和自由编排留作扩展。

## 工程组织

```text
src/pipeline/     API、执行器、Worker、存储、动画处理和页面
scripts/          安装、启动、故障演示、打包和清理
tests/           PostgreSQL、进程恢复及前端测试
docs/            设计、说明、技能来源和验证证据
.local/          本地数据库、产物、日志和临时实验（忽略）
.venv/           项目依赖（忽略）
delivery/        当前源码 ZIP 和摘要
```

所有开发文件集中在独立项目目录。数据库、产物与依赖不进入源码包；构建只使用已提交文件。

## 验证重点

- 创建请求立即返回；API 重启后任务和历史仍可查询。
- 步骤失败可重试，成功上游保留；永久错误和耗尽预算有明确终态。
- 真实中断 Worker、数据库或整套服务后，从已提交检查点恢复。
- 旧 Worker 的迟到写入被拒绝；状态与事件同事务提交。
- 缓存命中需通过文件校验，参数变化或文件损坏触发正确重算。
- 取消、搜索、归档、重复提交和窄屏交互可以演示。
- Linux CI、源码包摘要和公开访问分别核验。
