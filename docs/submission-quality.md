# v0.3 交互与可靠性改进

基于 v0.2（`f32cb6d`），结合修改建议和实际操作完善创建协议、参数复制、恢复信息和页面交互。沿用 FastAPI、PostgreSQL、独立 Worker 和原生前端。

## 改动说明

| 改进项 | 实现 |
| --- | --- |
| 创建意图使用稳定幂等键 | 原界面每次点击新建键，服务端幂等无法保护响应丢失后的重试。现在发送前持久化键和参数快照；重试、刷新后确认均使用原请求。 |
| 区分复制参数与结果复用 | 原按钮静默开启缓存、关闭故障。现在两个入口都打开可审查表单；复制完整保留配置，复用仅更改明确告知的两项。 |
| “每批耗时”含义不符 | 接入 batch_delay，普通步骤耗时放到高级设置；留空沿用 step_delay。支持 4–64 的任意整数帧数。 |
| 错误、预算、阻塞与恢复信息 | 展示实际 error_type、轮次/上限、next_run_at、阻塞祖先、恢复帧数、未重执行的成功上游。展示数据库记录的状态和耗时。 |
| 缓存来源与校验 | 通过 artifact → producing attempt → task 关联原始来源；展示指纹、SHA-256 和命中事件时间。说明这是历史校验，下载时重新检查。 |
| 页面与代码整理 | 直接标题、三个演示入口、可展开错误/原始事件、字号及窄屏滚动提示；创建意图、表单、详情、DOM 更新分模块，视图按职责拆函数。 |
| 轮询保持焦点/展开状态 | 按任务/步骤/attempt/event 键更新现有 DOM；输入表单不在轮询区域。状态摘要增减时也保留尝试表格；资源/事件容器独立更新。 |
| 架构 | 保留现有执行器，前端按职责拆成原生模块，未新增运行依赖。 |
| 发布 | v0.3.0 已同步至公开仓库，源码 ZIP 匿名下载摘要一致，Linux CI 的 33 项 pytest 与 4 项 Node 测试通过；[发布证据](evidence/release-v0.3-verification.json)。原本地证据保留。 |

## 创建协议与边界

- 使用当前标签页的 `sessionStorage`，存储发生在 POST 之前。保存失败则不发送请求，避免无法重试的写入。
- 请求发出后，表单锁定快照。关闭弹窗不取消服务端任务，首页保留“提交结果待确认”入口；刷新后可恢复。
- 超时、断网、5xx、无有效 task ID 的响应均保留原意图；得到有效 task ID 后才清除。409/422 也保留记录供检查，参数修正必须明确另建。
- “另建任务”明确提示旧请求可能已成功、可能产生第二个任务。确认后才清除原意图并允许编辑，新提交生成新键。不自动取消旧任务。
- 普通草稿尚未提交时不保存；标签页关闭、站点数据清除、切换浏览器/端口不在恢复保证内。不同标签页分别管理创建意图。
- 复制表单通过完整快照叠加展示字段，暂未展示字段不静默丢弃；未知字段仍由 API 严格校验。故障选择不会静默改缓存或时限，演示预设则明确预填配置。

## 验证记录

本轮新增 PostgreSQL/HTTP 测试覆盖前端意图模块 + 真实 API + 数据库单任务约束，以及跨多次缓存命中的原始生产者溯源。另有前端状态测试覆盖响应丢失/刷新、存储失败、畸形响应、明确另建和完整参数复制。

实际测试结果、浏览器任务 ID、截图和范围见 `evidence/quality-verification.json` 与 `evidence/tests-quality.xml`。本轮测试使用独立测试数据库；页面验证仅新增“质量验收”任务，未删除或改动原有任务及产物。

真实响应丢失的浏览器复现工具：

```bash
# 先启动正常本地服务；另一个终端运行：
.venv/bin/python scripts/response_loss_proxy.py
# 打开 http://127.0.0.1:8766，新建一个明确命名的验证任务。
# 代理在首次 POST 已收到 202 后切断响应；刷新页面，再确认原请求。
# 两次请求/响应记录在 .local/quality/response-loss.json；Ctrl+C 停止代理。
```

代理仅是显式运行的本地测试夹具，不加入正常启动流程，不提供终止 Worker 的网络接口。不要用它代理真实公网流量。

本版 Linux CI 已通过 33 项 pytest 和 4 项 Node 测试；一小时演练沿用 v0.2 的 3607.93 秒记录。真实 GPU、多机隔离、高并发压力、Compose 运行和完整无障碍审计属于后续验证范围。
